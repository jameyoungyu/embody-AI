## 一、不能签字的一处判定逻辑：2606.31494 的核查问错了问题

外部报告的判定链是：

> 该综述无实证数据拟合 → 未测量 ID→OOD 经验曲线 → **C1 致命撞车风险完全解除**。

**这条推理不成立。** 一篇综述**不需要做任何实验**，就足以抢走 C1 的概念贡献。

C1 的贡献目前有两层：

| 层 | 内容 | 会被什么抢走 |
|---|---|---|
| 概念层 | 指出 PDR 隐含的比例假设有问题、鲁棒性必须控制 nominal performance | **一句话的 critique 就能抢走**，无需实验 |
| 实证层 | 拟合闭环 ID→OOD 关系、证明非比例、证明随时域变化、证明改变排名 | 只有同类实证研究能抢走 |

外部报告只核查了实证层。**必须补查概念层。**

### 正确的核查方式（10 分钟，你有 arXiv 访问权）

打开 2606.31494 全文，在 metrics / evaluation 章节检索以下字符串：

```
drop rate            relative robustness       normalize
nominal              baseline performance      success rate
conditioned on       confound                  capability
```

**判定：**

| 综述里的情况 | C1 的处置 |
|---|---|
| 已明确指出「现有鲁棒性指标未控制 nominal performance / PDR 类指标有问题」 | 概念贡献被抢。C1 **仍可做**，但必须改写为「我们回答该综述提出的问题」，并把它作为 critique 的**出处**引用，而非仅作 motivation。Novelty 降至 **C−/B**，需重新评估是否值得 |
| 只有定义、分类学与既有协议梳理，未触及该 critique | C1 概念层与实证层都成立，按现计划推进 |

**在这一步之前，我不认可「威胁完全解除」这个表述。**

## 二、需要纠正的文献事实：C3 的 Layer 4 认定有误，且方向可能相反

外部报告称：「自动驾驶领域早在 2022–2023 年就发现了感知 mAP 与下游规划控制脱钩的问题（如 ST-P3 / UniAD）」。

本次独立检索的结果与此**不一致**：

1. **时间与出处都不对。** 该问题的奠基工作是
   **Learning to Evaluate Perception Models Using Planner-Centric Metrics**（arXiv **2004.08745**，PKL 指标，2020），
   比报告所述早 2–3 年，且与 ST-P3 / UniAD 不是同一回事（后两者是端到端驾驶架构，不是指标研究）。
   相关还有 **Transcendental Idealism of Planner**（2306.07276）。

2. **更关键——实证结论方向可能与 C3 的假设相反。**
   **On Offline Evaluation of 3D Object Detection for Autonomous Driving**（arXiv **2308.12779**，ICCVW 2023）
   直接研究离线检测指标能否预测闭环驾驶结果，检索到的表述是：
   - nuScenes Detection Score **比 mAP 更能预测**闭环驾驶结果；
   - planner-centric 的 ADE 与 Driving Score / 碰撞数的相关系数为 **0.78 / 0.77**，
     但**弱于 mAP 类指标**的相关性。

   也就是说，最近邻领域给出的先验是「**检测指标与下游表现相关性尚可**」，
   而不是 C3 假设的「脱钩」。

### 对 C3 的后果

- C3 的 **H2**（AP 与执行成功率的 Spearman 秩相关在特定 corruption 下崩到 <0.4）
  **失败概率被显著上调**。
- 按用户自定 Layer 4 规则：跨领域已有成熟理论时，迁移本身不构成贡献。
  C3 的机制部分（几何容差 vs 力闭合敏感性、Top-1 排序翻转）必须做成**抓取特有**的论证，
  不能靠「AD 也这样」来立论。
- 另外，**物理仿真执行评测在抓取领域已是常规做法**（Isaac Gym 抬升判定；Sim-Grasp、
  DexGraspNet 2.0、AO-Grasp vs CGN 等都同时报告 AP 与仿真成功率）。
  所以 C3 未被占的部分要收窄为：**在系统 corruption 扫描下，两者秩相关的崩溃行为**——
  而不是「没人比较过 AP 与执行成功率」。

## 三、评级口径不一致

外部报告给出 C1 = 「B+ / C+」、C3 = 「B / C+」，并据此建议全速推进。

但按本项目 `03_candidates.md` 采用的 Novelty 分级（源自任务定义）：

- **B = 高度相似，仅数据集/模型/领域不同 → 默认低优先级**
- **C = 邻近研究存在但核心科学问题不同 → 有潜力**

**B 是减速信号，不是绿灯。** 且 `B+ / C+` 不在既定分级里。
建议统一回 A/B/C/D 单档，否则分级失去决策功能——这套分级的唯一用途就是触发行动。

## 四、C3 Pilot 的 1–2 天估计偏乐观

GraspNet-1B 测试集为 90 个场景 × 256 视角。若做 4 个模型 × ~10 种 corruption × 3 级强度
= 120 组模型-条件，每组都跑全量测试集再加物理执行判定，1–2 天不现实。

可行做法（需在方案里写死）：
- 场景/视角**分层子采样**（例如每场景固定抽 16 个视角，覆盖 seen/similar/novel 三档）；
- **先验证子采样本身不改变干净条件下的模型排名**，否则后面所有结论都建立在采样噪声上；
- 物理执行只评 Top-K（K=1 与 K=10 分别报），因为真机只执行 Top-1，这也正是「排序翻转」机制的检验点。
